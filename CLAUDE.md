# compo-space.ru — правила для Claude

Сайт Compo OneSpace: Astro (статика) + Sveltia CMS + Yandex Cloud.
Подробное описание устройства — в `README.md`. Прочитай его перед первой задачей.

## Как работать

- Всегда создавай ветку и pull request. Напрямую в `main` не пиши: каждое слияние в `main` сразу выкладывает сайт.
- Перед тем как открыть PR, запусти `npm run build`. Если сборка падает — исправь, не открывай сломанный PR.
- В описании PR коротко и по-русски напиши, что изменилось и где это увидеть: адрес страницы и блок.
- Меняй только то, о чём просят. Не переделывай вёрстку, отступы и тексты, которые не упоминались.

## Где что лежит

- Тексты страниц — `src/content/pages/<адрес>.json`: поле `blocks`, порядок блоков = порядок на странице. Главная — `index.json`.
- Статьи блога — `src/content/blog/<адрес>.md`. Новые статьи создавай с `draft: true`, если не сказано опубликовать.
- Хедер, футер, меню, контакты, попапы, юридическая информация — `src/content/site.json`.
- Вёрстка блоков — `src/components/blocks/*.astro`. Стили — `public/styles/*.css`.
- Интерактив (табы, калькулятор, FAQ) — `public/scripts/page.js`. Форма — `public/scripts/os-form.js`.
- Поля админки — `public/admin/config.yml`.

## Если добавляешь новое

- **Новая страница** — новый JSON в `src/content/pages/`. Маршрут создавать не нужно, его собирает `src/pages/[...slug].astro`. В меню страница попадёт, только если её добавить в `site.json → nav`.
- **Новый тип блока** — компонент в `src/components/blocks/`, строка в `BlockRenderer.astro` и описание полей в `public/admin/config.yml` (раздел `types` у коллекции `pages`). Без последнего блок нельзя будет добавить из админки.
- **Новое поле у блока** — добавь его и в компонент, и в `config.yml`, иначе редактор его не увидит.
- **Новый попап** — запись в `site.json → popups` и вариант `popup:<id>` во всех списках «Куда ведёт» в `config.yml`.

## Стиль и тексты

- Палитра: тёмно-синий `#0B1D3A`, акцент `#0077FF`, вторичный текст `#5B6B8C`, фон `#F5F8FC`. Шрифты: Manrope для заголовков, Inter для текста, IBM Plex Mono для меток. Новых цветов не вводи.
- Тон: коротко, конкретно, по-деловому тепло. Без канцелярита. Не используй слово «обязан».
- Не пиши «Вход 1», «точка входа» и другие внутренние рабочие термины — только названия направлений: «Проекты и маржа», «AI без утечки» и т. п.
- Говорим «лицензия», не «подписка» и не «договор».
- Не придумывай цифры, клиентов и кейсы. Если для задачи нужны данные, которых нет, спроси в комментарии.

## Форма и персональные данные

- Обязательные поля: имя, телефон (маска `+7 (XXX) XXX-XX-XX`), email (с `@`) и согласие с политикой обработки персональных данных. Не ослабляй эти проверки.
- Чекбокс согласия на рекламные материалы — необязательный.
- Заявки должны храниться на серверах в РФ (152-ФЗ). Внешние сервисы для приёма форм без согласования не подключай.
