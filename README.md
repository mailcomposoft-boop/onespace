# compo-space.ru — сайт Compo OneSpace

Astro (статика) + Sveltia CMS + Yandex Cloud.

## Запуск

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # готовый сайт в dist/
```

Нужен Node.js 20+.

## Как устроено

```
src/
  content.config.ts           схемы коллекций pages и blog
  content/
    site.json                 хедер, футер, контакты, юр. информация, раздел блога
    pages/*.json              продуктовые страницы: SEO + список блоков
    blog/*.md                 статьи блога
  layouts/Base.astro          <head>, SEO, хедер, футер, подключение скриптов
  components/
    Header.astro, Footer.astro
    BlockRenderer.astro       тип блока из JSON → компонент
    blocks/                   Hero, Problem, Solution, Pilot, Shots, Stack,
                              Calculator, Steps, Faq, Text, LeadForm
    graphics/HeroAi.astro     графика первого экрана (кодом, в CMS не правится)
    blog/PostCard.astro       карточка статьи
  pages/
    [...slug].astro           все продуктовые страницы, включая главную (index.json)
    blog/index.astro          список статей
    blog/[slug].astro         статья
    blog/tag/[tag].astro      статьи по тегу
public/
  styles/                     os.css, header.css, footer.css
  scripts/
    page.js                   табы, калькулятор, FAQ, анимации появления
    header.js                 меню и бургер
    os-form.js                форма заявки
  admin/                      Sveltia CMS: index.html + config.yml
  images/                     логотип, загрузки из CMS (images/uploads)
.github/workflows/deploy.yml  сборка и выкладка в Object Storage
```

Тексты, списки и скриншоты лежат в JSON и Markdown — их правит редактор в `/admin`.
Вёрстка блоков, графика первого экрана и формулы калькулятора — в коде.

## Новая продуктовая страница

В админке: **Страницы → Новая страница**.

1. Название и адрес (`url`, латиницей через дефис) — адрес станет `compo-space.ru/<url>`.
2. SEO: title, description, картинка для соцсетей.
3. **Блоки страницы → Добавить блок**: выберите тип, заполните поля, перетащите в нужное место.
   Доступно 11 типов: первый экран, проблема, решение, пилот, скриншоты в табах,
   сравнение стека, калькулятор, шаги, FAQ, произвольный текст, форма заявки.
4. Снимите «Черновик» и опубликуйте.

Чтобы страница появилась в меню, добавьте её в **Общие блоки → Меню**.
Файл `index` — главная страница сайта.

Новый *тип* блока добавляет разработчик: компонент в `components/blocks/`,
строка в `BlockRenderer.astro` и описание полей в `public/admin/config.yml`.

## Кнопки и попапы

У каждой кнопки в блоках (первый экран, пилот, калькулятор) и у кнопки в хедере
есть поле «Куда ведёт». Варианты:

- **Попап** — Демо, Пилот, Точный расчёт, Консультация. Это значение по умолчанию:
  основная кнопка первого экрана → «Демо», пилот → «Пилот», калькулятор → «Точный расчёт»,
  хедер → «Консультация»;
- **Якорь на странице** — форма, калькулятор, сравнение стека;
- **Своя ссылка** — любой адрес в поле ниже: `/blog`, `https://…`.

Попапы общие для всего сайта: **Общие блоки → Попапы**. У каждого — заголовок, текст,
название формы для заявки и сообщение после отправки. Новый попап добавляется там же,
а в выпадающий список кнопок — строкой в `public/admin/config.yml`.
Попап можно открыть и снаружи: `compo-space.ru/#popup:demo`.

## Блог

В админке: **Блог → Новая статья**. Заголовок, анонс, дата, обложка, теги, текст в Markdown.
Новые статьи создаются черновиками — снимите отметку, чтобы опубликовать.

- `/blog` — все статьи, новые сверху, облако тегов;
- `/blog/<адрес>` — статья, блок «Читайте также» по общим тегам и CTA на демо;
- `/blog/tag/<тег>` — статьи по тегу.

В репозитории лежит пример `primer-stati.md` — он черновик и на сайт не попадает.

## Админка

1. Репозиторий уже прописан в `public/admin/config.yml`: `mailcomposoft-boop/onespace`.
2. Вход через GitHub: Sveltia CMS работает с личным токеном или через OAuth-приложение
   (см. документацию Sveltia, раздел «Backends → GitHub»).
3. Откройте `https://compo-space.ru/admin` — там разделы «Страницы», «Блог» и «Общие блоки».

Чтобы правки шли через pull request, раскомментируйте `publish_mode: editorial_workflow`.

## Выкладка в Yandex Cloud

1. Создайте бакет Object Storage с хостингом статического сайта (индекс `index.html`, ошибка `404.html`).
2. Создайте сервисный аккаунт с ролью `storage.editor` и статический ключ доступа.
3. В Settings → Secrets репозитория добавьте:
   - `YC_ACCESS_KEY_ID`, `YC_SECRET_ACCESS_KEY` — статический ключ;
   - `YC_BUCKET` — имя бакета;
   - `YC_CDN_RESOURCE_ID`, `YC_SA_KEY` — если подключён CDN (необязательно).
4. Каждое слияние в `main` собирает сайт и выкладывает его в бакет.

Домен `compo-space.ru` направляется на CDN-ресурс или напрямую на бакет. SSL — через Certificate Manager.

## Форма заявки

Адрес приёма задаётся в CMS: «Общие блоки» → «Адрес приёма заявок» (`form_endpoint`).
Пока он пустой, форма проверяет поля, но заявку не отправляет. Обработчик —
отдельная функция в Yandex Cloud Functions (следующий шаг): хранение заявок
в РФ по 152-ФЗ, отправка в почту или CRM.
